# Blog Patterns - Structure & SEO Guidelines

## Blog Post Architecture

### Title Formula
**Pattern**: [Number/How to] + [Specific Benefit] + [Target Audience/Context]
- "5 Automation Tools That Save 2 Hours Daily"
- "How to Build Systems That Actually Scale"
- "Why Your Productivity Stack Is Failing (And What to Do Instead)"

### Meta Structure (First 100 words)
```markdown
---
title: "Your SEO-Optimized Title"
description: "150-character summary focusing on reader benefit"
tags: ["productivity", "automation", "tools"]
publishDate: "YYYY-MM-DD"
readingTime: "X min read"
---
```

## Content Structure

### Hook Introduction (50-100 words)
1. **Problem statement** - What pain point does this solve?
2. **Personal stake** - Your experience with this issue
3. **Value preview** - What reader will gain
4. **Roadmap sentence** - Brief overview of what's coming

**Template:**
> After [specific struggle], I discovered [insight/solution]. Here's the [framework/system/approach] that [specific benefit] and how you can [implement it/avoid my mistakes/get results].

### Body Section Pattern

#### H2: Problem/Context Setting
- Define the specific challenge
- Quantify the impact (time, money, frustration)
- Share relatable example or story

#### H2: Solution Framework  
- Present your approach/system
- Break into 3-5 clear steps
- Include decision criteria or principles

#### H2: Implementation Guide
- Specific tools and setup instructions
- Common pitfalls to avoid
- Success metrics to track

#### H2: Advanced Applications
- How to scale or customize
- Integration with other systems
- Long-term maintenance

### Conclusion Structure (75-100 words)
1. **Key insight summary** - One-sentence main takeaway
2. **Next step recommendation** - Single, specific action
3. **Call-to-action** - Comment prompt, share request, or resource

## SEO Optimization

### Keyword Strategy
- **Primary keyword** in title, first H2, and conclusion
- **Secondary keywords** in H2s and naturally throughout
- **Long-tail variations** in subheadings and examples
- **Related terms** for semantic SEO coverage

### Header Hierarchy
```markdown
# H1: Blog Title (One per post)
## H2: Main Section Headers (3-5 per post)
### H3: Subsection Headers (Use sparingly)
#### H4: Only for detailed breakdowns
```

### Internal Linking
- Link to 2-3 related posts within content
- Use descriptive anchor text, not "click here"
- Link to foundational content for new readers

## Content Guidelines

### Length Targets
- **Standard posts:** 1,200-1,800 words
- **Deep dives:** 2,500-4,000 words  
- **Quick tips:** 800-1,200 words

### Engagement Elements
- **Numbered lists** for processes and steps
- **Bullet points** for features and benefits
- **Code blocks** for technical examples
- **Blockquotes** for key insights or external quotes
- **Screenshots** for tool demonstrations

### Example Integration
- Include specific, real-world examples
- Share actual numbers and results
- Use case studies from personal experience
- Provide templates or frameworks readers can copy

## Quality Checklist

### Pre-Publication Review
- [ ] Title promises specific value
- [ ] Introduction hooks within 50 words
- [ ] Each H2 section delivers on its promise
- [ ] Examples support main points
- [ ] Conclusion reinforces value and next steps
- [ ] Meta description under 155 characters
- [ ] Primary keyword appears 3-5 times naturally

### Readability Standards
- [ ] Flesch Reading Ease score above 60
- [ ] Average sentence length under 20 words
- [ ] Paragraphs under 4 sentences
- [ ] Transition phrases between sections
- [ ] Active voice in 75%+ of sentences

## Content Validation

### Value Test Questions
1. **Specificity**: Could this advice apply to anyone, or is it targeted?
2. **Actionability**: Can reader implement within 1 week?
3. **Uniqueness**: What makes this different from existing content?
4. **Completeness**: Does it answer the question fully?

### Reader Experience Test
- **Scan test**: Can someone get value by reading only headers and bullets?
- **Implementation test**: Are steps clear enough to follow?
- **Outcome test**: Will reader know if they've succeeded?

## File Naming Convention

**Pattern**: `YYYY-MM-DD-url-slug.md`

**Examples:**

- `2024-03-22-productivity-stack-failing.md`
